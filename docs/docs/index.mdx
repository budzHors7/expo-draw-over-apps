# Expo Draw Over Apps

`expo-draw-over-apps` manages Android overlay permission, named floating windows, and their lifecycle. Your application supplies all window content through one of two roots:

- `ReactNativeWindow` renders React Native children.
- `NativeWindow` renders `@expo/ui/jetpack-compose` children directly.

This release is an Expo SDK 58 hard cut. It uses the Expo Modules 2.0 API and does not include the former compatibility containers or a packaged Compose renderer.

:::info Android development build required

The package contains Android native code and cannot run in Expo Go. Use a development or production build.

:::

## Install

Run these commands from your Expo SDK 58 app:

```bash
npm install expo-draw-over-apps
npx expo install @expo/ui react-native-reanimated react-native-worklets
npx expo prebuild --platform android
```

If your project already has an `android` directory, rebuild the app after installing the package instead of regenerating files you maintain manually.

For a bare React Native project, [install Expo modules](https://docs.expo.dev/bare/installing-expo-modules/) before installing this package.

## Choose a window

| Root | Children | Size behavior |
| --- | --- | --- |
| `ReactNativeWindow` | React Native views | Animates finite `width`, `height`, and `borderRadius` values with Reanimated |
| `NativeWindow` | Expo UI Jetpack Compose components | Delegates layout and animation to Compose modifiers inside an Expo UI `Host` |

Start with [permission setup](/docs/tutorial/permission-flow), then copy either the [React Native window](/docs/tutorial/react-native-window) or [native Compose window](/docs/tutorial/native-window) example.

## Android configuration

The package contributes `android.permission.SYSTEM_ALERT_WINDOW` and its overlay service through the library manifest. Expo autolinking registers the native module; the default setup does not require hand-editing `AndroidManifest.xml`.

Use static, non-sensitive bubble IDs and shared-value keys. They cross the JavaScript/native boundary and are normalized for stability, not privacy.
